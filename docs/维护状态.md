# 维护状态（2026-09-19）

> 作用：把**已经拍板的取舍**写下来，免得同一件事被反复当待办讨论。
> 纪律：只有明确做过决定的事才进本文件；每条写"谁在什么场景下拍的 + 理由"。

## 在做的

- **DSH 主宿主**：本仓的主线。0.11.1 起包声明了 `dsh.bundle.patch`，`dsh plugin add` 装完自动挂设置面板。
- 发布通道：**GitHub Release 附件**（`npm pack` 出来的 tarball）。发布流程见 [CONTRIBUTING.md](../CONTRIBUTING.md) 的「发布清单」。

## 明确不做的

### 1. 暂不发 npm（2026-09-19 维护者拍板）

- 现状：目前没有"求上 npm"的声音，Release 附件通道已经够用（零依赖，一条命令装成）。
- 代价与前提：真要发时 —— 切回官方 registry + `npm login`，之后每次发版 `npm publish` 约几 MB 流量。
- 不改判据：等真有用户/下游拿不到 Release 附件时再动。

### 2. ZCode 适配器**暂停**开发（2026-09-19 维护者拍板，非永久）

- **原因**：ZCode 最近做了一件引起公愤的事 —— **快照所有用户的工作区**。风评未好转前，不在这一侧投入。
- **决定**：**代码保留、不删**（不是"停用"，是"暂停"）。等 ZCode 风评好转、用的人多起来再回来更新这一侧。
  README 里对应的表述已标明"停止开发 / 仅作历史保留"，避免给用户造成"还在维护"的误解。
- 代价与现状：`adapters/zcode/` 停在 0.9.0 那一代（0.10.0 起的预设库、酒馆卡、`dsh.bundle` 都与它无关）；
  `scripts/sync-core.mjs` 仍会把 `core/` 同步到 vendor 副本，所以底层能力不会悄悄腐烂。
- **恢复条件（改判据）**：ZCode 风评好转且用户量上来 → 重新评估这一侧的同步与真机回归。
- 补充：删的代价与做法已评估过（要连带改 `sync-core.mjs`、`tests/zcode-hook.mjs` 与 README 六处表述），
  本次不执行；将来真要删，历史随时可取（`git show v0.11.1:adapters/zcode/...`）。

### 3. 不追"角色库体量"（2026-09-20 维护者拍板）

- 触发来源：2026-09-20 对标同类（agency-agents 153,680★ / 中文版 20,817★、277 个角色、20 个工具）。
- **不做**：不往本仓塞角色/部门内容库。理由：那是内容运营，与本仓"套件私有 + 只开源本体 + 出厂空白"
  的定位正面冲突；且 277 个角色的注入体量与"每轮注入小、默认零行为改变"这条护城河互斥。
- 代价：在"开箱即用"这一项上永远不比人家强 —— 接受。要比就比**纪律与默认安全**（可实测）。

### 4. 不抄宿主的周边功能（2026-09-20 维护者拍板，同日）

- 触发来源：同上对标中 `dsh-guise` 的余额预警 / 电量模式 / 用量统计。
- **不做**：这类是宿主层周边，与人设引擎无关，且那类功能在做它的插件里也没被验证过需求（该仓 ★0）。
- 改判据：有人明确要求"人设插件里看用量"，再议。

### 5. 跨平台适配器暂缓（2026-09-20 维护者拍板，同日）

- 现状：真实差距在分发面（对手支持 14–20 个工具，本仓主宿主只有 DSH）。
- **决定**：本轮不做；要做的形态是**薄适配层**（Claude Code / Cursor 的 AGENTS.md / SKILL 片段 + 人设包导出），
  **不是**复活第 2 条里暂停的 ZCode 侧。
- 改判据：真正出现"我要把它装到别的 IDE 上"的需求时再动。
